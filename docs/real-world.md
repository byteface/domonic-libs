# Real-world JS library sweep

Generated by `python -m domonic_libs.realworld`. Each row fetches a real,
popular library's actual published bundle live over the network -- not
vendored, not adapted for myjs -- through `domonic_libs.acorn.interpret`.
A curated few get hand-written smoke assertions (real API calls); the rest
just have to load and expose a real global, checked generically. A load
error or a failing case is a genuine interpreter/domonic wrinkle candidate,
found the same way the sloppy-mode `this`, ES5-prototype-chain, ES5
`instanceof` / `Object.create`, and `Object.prototype.toString` bugs were:
run something real, see what breaks.

jsdelivr's bare `npm/<pkg>` often resolves to a package's CommonJS build
rather than a browser bundle. A row that fails with `exports is not defined`
is retried once with `commonjs=True` (myjs's `require` / `module` /
`exports`); `[multi-file CommonJS package]` marks the ones that then need a
bundler to resolve their own `require('./…')` calls.
